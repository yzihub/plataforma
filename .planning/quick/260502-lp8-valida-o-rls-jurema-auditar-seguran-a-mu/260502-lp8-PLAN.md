Catálogo de queries de auditoria (Postgres / Supabase):

```sql
-- 1) RLS está ativo?
SELECT schemaname, tablename, rowsecurity
FROM pg_tables
WHERE schemaname = 'public'
  AND tablename IN (
    'leads','imoveis','jurema_deals','jurema_property_matches',
    'contracts','agent_metrics_events','brokers','profiles'
  )
ORDER BY tablename;

-- 2) Quais policies existem?
SELECT
  schemaname, tablename, policyname,
  permissive, roles, cmd, qual, with_check
FROM pg_policies
WHERE schemaname = 'public'
  AND tablename IN (
    'leads','imoveis','jurema_deals','jurema_property_matches',
    'contracts','agent_metrics_events','brokers','profiles'
  )
ORDER BY tablename, cmd, policyname;

-- 3) Quais roles têm GRANT em cada tabela?
SELECT table_name, grantee, privilege_type
FROM information_schema.table_privileges
WHERE table_schema = 'public'
  AND table_name IN (
    'leads','imoveis','jurema_deals','jurema_property_matches',
    'contracts','agent_metrics_events','brokers','profiles'
  )
  AND grantee IN ('anon','authenticated','service_role','public')
ORDER BY table_name, grantee, privilege_type;

-- 4) Verifica colunas tenant_id (se existem em cada tabela)
SELECT table_name, column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name IN (
    'leads','imoveis','jurema_deals','jurema_property_matches',
    'contracts','agent_metrics_events','brokers','profiles'
  )
  AND column_name = 'tenant_id'
ORDER BY table_name;
```

Critério de classificação por tabela:

- **Segura**: rowsecurity=true + policies cobrem SELECT/INSERT/UPDATE/DELETE com filtro `tenant_id = auth.jwt() ->> 'tenant_id'` (ou equivalente) + anon NÃO tem grant SELECT direto.
- **Vulnerável**: rowsecurity=true mas alguma policy aceita anon, ou USING/WITH CHECK não filtra tenant_id, ou DELETE livre, ou anon tem privilégios em tabela sensível.
- **Bloqueada por falta de policy**: rowsecurity=true mas zero policies (ninguém consegue ler — causa 403 silencioso).
- **Crítica (RLS off)**: rowsecurity=false em tabela com tenant_id (vazamento total).

Regras do projeto (CLAUDE.md):
- Frontend usa apenas anon + authenticated. service_role apenas no backend Agno/YZI OS.
- Cada tabela deve isolar por tenant_id.
- DEPL-03 é blocker — relatório deve permitir destravar a fase de deploy.
