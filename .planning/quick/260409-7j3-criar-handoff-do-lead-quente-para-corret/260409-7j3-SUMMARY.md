# Quick 260409-7j3: Handoff do Lead Quente para Corretor — Summary

**One-liner:** Sub-workflow `handoff_corretor` criado e encadeado no `setar_lead_quente` via executeWorkflow node, enviando resumo estruturado (nome, telefone, objetivo, faixa_valor, bairro, imovel_ref, localizacao_visita) ao corretor via webhook configuravel com fallback httpbin.

## What Was Built

### Task 1 — handoff_corretor.json (CREATED)

Workflow n8n com 3 nodes em sequencia linear:

1. **Dados do Lead** (`executeWorkflowTrigger`) — recebe 6 inputs: `phone`, `tenant_id`, `lead_name`, `lead_status`, `lead_score`, `metadata_json`
2. **Montar Resumo** (`Code`) — faz `JSON.parse(metadata_json)` com try/catch, monta objeto `resumo` e `mensagem_texto` formatada para WhatsApp
3. **Enviar Handoff** (`HTTP Request POST`) — POST para `$vars.HANDOFF_WEBHOOK_URL` (fallback: `https://httpbin.org/post`) com body `{ type: 'lead_handoff', tenant_id, resumo, mensagem_texto }`

### Task 2 — setar_lead_quente.json (UPDATED)

Adicionado node 6 **Handoff Corretor** (`executeWorkflow`, typeVersion 1.2) na posicao `[1456, 0]` apos o PATCH Lead:
- `mode: "each"`
- `workflowId: "={{ $vars.HANDOFF_WORKFLOW_ID }}"`
- Passa `phone`, `tenant_id`, `lead_name`, `lead_status`, `lead_score`, `metadata_json` extraidos do response do PATCH Lead (`return=representation`)
- Connection `PATCH Lead → Handoff Corretor` adicionada
- Nodes 1-5 preservados com IDs e parametros identicos
