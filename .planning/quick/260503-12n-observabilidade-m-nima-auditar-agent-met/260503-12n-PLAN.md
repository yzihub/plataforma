   a) Query `agent_metrics_events` — todos eventos do agent 'jurema' nos últimos 30 dias:
      ```ts
      const since30d = new Date(Date.now() - 30 * 24 * 60 * 60 * 1000).toISOString();
      admin
        .from("agent_metrics_events")
        .select("id, agent_name, event_type, project_id, created_at")
        .eq("agent_name", "jurema")
        .gte("created_at", since30d)
        .order("created_at", { ascending: false })
        .limit(500)
      ```
      IMPORTANTE: NÃO filtrar por tenant_id na query de eventos — a tabela não tem tenant_id como coluna direta (validado no E2E). O escopo é dado por `agent_name='jurema'` (cada agente é exclusivo de um tenant). Esta é uma decisão consciente, não uma falha de escopo.

   b) Query `jurema_deals` — agregados do tenant atual (RLS-safe via tenant_id):
      ```ts
      admin
        .from("jurema_deals")
        .select("id, deal_stage, lead_score, qualification_status")
        .eq("tenant_id", tenantId)
      ```

4. Computar agregados em JS (NÃO calcular regra de negócio — apenas contagens):
   - `events_total = events.length`
   - `events_24h` e `events_7d` filtrando por `created_at`
   - `by_event_type`: `Map<event_type, {count, count_24h, count_7d}>` reduzindo o array, ordenado por `count` desc
   - `deals_total = deals.length`
   - `deals_qualified = deals.filter(d => (d.lead_score ?? 0) >= 70).length` (limiar 70 é apenas filtro DE EXIBIÇÃO, vem direto do score já calculado pelo backend; frontend NÃO está calculando score)
   - `deals_in_corretor_stage = deals.filter(d => d.deal_stage === 'corretor').length`
   - `recent_events`: primeiros 50 eventos da query (já vêm ordenados desc)

5. Retornar `NextResponse.json({ ok: true, tenant_id, generated_at: new Date().toISOString(), totals, by_event_type, recent_events }, { status: 200 })`.

6. Tratamento de erro: try/catch externo + log via `console.error("[GET /api/observabilidade/agent-metrics]", err)` + `{ error: "Erro interno do servidor" }` 500. Em queryError individual, logar e retornar 500.
