# Phase quick-260503-12n Plan 01: Observabilidade Mínima — agent_metrics_events Summary

**One-liner:** Página read-only /cockpit/observabilidade com KPI strip TailAdmin + 2 tabelas auditando eventos reais da Ju via GET /api/observabilidade/agent-metrics (30d, sem mocks).

## What Was Built

### Task 1 — GET /api/observabilidade/agent-metrics

Rota somente leitura que retorna:

- `totals`: events_total, events_24h, events_7d, deals_total, deals_qualified (score>=70), deals_in_corretor_stage
- `by_event_type`: array ordenado por count desc com contagens 24h/7d/30d
- `recent_events`: 50 eventos mais recentes

Padrão DEV_BYPASS idêntico a `src/app/api/imoveis/route.ts`. Em produção, resolve tenant_id via profiles. Em dev bypass, usa DEV_JUREMA_TENANT_ID.

**Decisão crítica de schema:** `agent_metrics_events` não possui coluna `tenant_id`. Escopo feito por `agent_name='jurema'` — cada agente pertence a um tenant.

### Task 2 — Página + Client Component + Sidebar

**`src/app/cockpit/observabilidade/page.tsx`:** Server component thin wrapper com `export const dynamic = "force-dynamic"`.

**`src/components/yzihub/AgentMetricsClient.tsx`:** Client component com:
- Loading skeleton `animate-pulse` (6 cards + 2 table skeletons)
- Error state (caixa vermelha)
- Empty state honesto (quando events_total === 0)
- KPI strip 6 cards (TailAdmin `rounded-2xl border bg-white dark:bg-white/[0.03]`)
- Tabela "Eventos por tipo" com colunas Tipo | 24h | 7d | 30d
- Tabela "Eventos recentes" com colunas Quando | Agente | Tipo | Project ID
- Rodapé com `generated_at` em pt-BR e tenant truncado

**`src/layout/AppSidebar.tsx`:** Item `Observabilidade` adicionado na seção Admin com `adminOnly: true`, antes de "Teste Ju", usando `BoltIcon` já importado.

## Schema Real Auditado

Colunas usadas de `agent_metrics_events` (validado via E2E-REPORT do plano 260502-kis):

```
id          uuid
agent_name  text   (ex: 'jurema')
event_type  text   (ex: 'message_received', 'stage_changed', 'property_options_requested')
project_id  uuid   (= deal_id no caso da Ju)
created_at  timestamptz
```

Event types esperados segundo E2E: `message_received`, `stage_changed`, `property_options_requested`, `property_search_failed`, `handoff_requested`.

Colunas usadas de `jurema_deals`:

```
id, deal_stage, lead_score, qualification_status, tenant_id
```
