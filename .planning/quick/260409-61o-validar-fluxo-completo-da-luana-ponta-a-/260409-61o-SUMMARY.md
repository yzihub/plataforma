## Key Findings

### BUG Found: status='lead_quente' Rejected by DB Constraint

The `leads` table has a CHECK constraint accepting only English values: `new`, `contacted`, `qualified`, `proposal`, `won`, `lost`.

The `setar_lead_quente` workflow (260409-5w2) sends `status: 'lead_quente'` which returns HTTP 400. Similarly `main workflow` sends `novo` and `atualizar_qualificacao` sends `qualificado` — all rejected.

**Impact:** When workflows execute against real leads, status updates fail silently (depending on error handling). The mechanics (metadata merge, score update) are correct — only the status values need to be mapped.

**Fix needed:** Either update workflows to use English status values (`new` → `contacted` → `qualified`), OR add Portuguese values to the DB CHECK constraint. This is a separate fix task.

### Tenant ID Mismatch

The demo tenant `aaaaaaaa-0002-0002-0002-000000000002` (Jurema Brokers seed) has no imoveis. The real production tenant `82cc7aa9-fc6e-4f37-8d8e-8a71c1691361` has 33 published imoveis. The n8n workflows must be configured with the real tenant_id.
