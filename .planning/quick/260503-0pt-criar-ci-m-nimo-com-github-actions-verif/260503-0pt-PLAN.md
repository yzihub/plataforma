  <name>Task 2: Criar workflow GitHub Actions .github/workflows/ci.yml</name>
  <files>.github/workflows/ci.yml</files>
  <action>
Criar diretório `.github/workflows/` (não existe) e arquivo `ci.yml` com o pipeline mínimo.

Conteúdo exato do arquivo:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  validate:
    name: Lint, Typecheck, Test, Build
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Typecheck
        run: npm run typecheck

      - name: Lint
        run: npm run lint

      - name: Test
        run: npm test

      - name: Build
        run: npm run build
```

Regras críticas:
- Triggers limitados a `push`/`pull_request` na branch `main` — sem cron, sem outras branches.
- Job único `validate` — não criar matrix, não criar jobs paralelos (escopo mínimo).
- Usar `actions/checkout@v4` e `actions/setup-node@v4` (versões major estáveis).
- Cache npm via `cache: 'npm'` no setup-node — não adicionar `actions/cache` separado.
- `npm ci` (não `npm install`) porque há `package-lock.json` no repo.
- Ordem dos passos: typecheck → lint → test → build (falha rápida nos checks baratos).
- Sem `env:` com secrets — o `next build` desta plataforma roda sem precisar de envs de runtime para passar (next 16 valida apenas tipo/sintaxe na build).
- NÃO adicionar steps de deploy, NÃO adicionar `vercel`, NÃO adicionar testes E2E.
- NÃO adicionar permissions, concurrency, matrix de versões — manter minimalista.
- timeout-minutes: 15 protege contra workflow travado.

Se o `npm run build` precisar de envs públicas placeholder para não quebrar (NEXT_PUBLIC_*), reportar no SUMMARY mas NÃO adicionar variáveis falsas neste plano — a build atual já passa em local sem envs (validado em 260502-rxe).
