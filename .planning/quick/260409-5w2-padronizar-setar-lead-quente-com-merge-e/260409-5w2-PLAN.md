# Quick 260409-5w2: Padronizar setar_lead_quente com merge e contexto

## Goal

Migrar workflow `setar_lead_quente` (n8n ID: `QZ3VcIrxE6BRtCpj`) de Airtable para Supabase REST API.
Adicionar GET do lead antes do PATCH, merge de metadata, e retornar array com campos normalizados.

## Context

- **Workflow atual:** Trigger → Prepara Dados Airtable → Update record (Airtable) → Code
- **Problema:** usa Airtable; sem GET antes do PATCH; sem merge de metadata
- **Tenant ID Jurema:** `aaaaaaaa-0002-0002-0002-000000000002`
- **Tabela:** `leads` (phone = chave de busca junto com tenant_id)

## New Architecture

```
Trigger → Normalize → Get Lead (HTTP GET) → Build Metadata → PATCH Lead (HTTP PATCH)
```

## Implementation

### Node 1 — Trigger (update inputs only)
- Renomear para `Dados recebidos da Luana`
- Inputs: phone, tenant_id, localizacao_visita

### Node 2 — Normalize (replace Prepara Dados Airtable)
- Limpa phone (remove non-digits)
- Passthrough: tenant_id, localizacao_visita

### Node 3 — Get Lead (replace Update record Airtable)
- HTTP GET `/rest/v1/leads`
- SELECT: id, tenant_id, phone, name, status, score, metadata
- Filtro: tenant_id=eq.X & phone=eq.Y

### Node 4 — Build Metadata (replace Code in JavaScript)
- Referencia `$('Normalize').first().json` para phone/tenant_id/localizacao_visita
- Merge: `{ ...antigo, localizacao_visita }` (preserva dados anteriores)
- Campos fixos: status='lead_quente', score=3

### Node 5 — PATCH Lead (new node)
- HTTP PATCH `/rest/v1/leads`
- Filtro: tenant_id=eq.X & phone=eq.Y
- Body: { status, score, metadata }
- Header: Prefer: return=representation
